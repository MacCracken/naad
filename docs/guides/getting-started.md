# Getting started with naad

## Build

```sh
cyrius deps                              # resolve dependencies into lib/
cyrius build src/main.cyr build/naad     # compile the smoke binary
cyrius test                              # auto-discovers and runs every tests/**/*.tcyr
```

`cyrius test` with no argument is what CI runs. While working a single module,
`cyrius test tests/<module>.tcyr` runs just that suite — both forms are real.

**Serialize every `cyrius` call.** `cyrius test`/`build`/`deps` re-resolve
dependencies and race on `cyrius.lock`; two concurrent runs corrupt it. If more
than one agent or shell may touch this checkout, wrap each invocation:

```sh
flock /tmp/naad-build.lock cyrius test
```

## Layout

- `src/<module>.cyr` — one file per library module, flat namespace, no `include`
  lines between them. The Rust subdirectories (`rust-old/src/{synth,oscillator,
  acoustics}/`) are flattened into descriptive names here — `oscillator/` and
  `acoustics/` take a module prefix (`osc_core.cyr`, `acoustics_fdn.cyr`),
  `synth/` keeps its bare names (`fm.cyr`, `granular.cyr`).
- `tests/<module>.tcyr` — the matching parity suite, auto-discovered by `cyrius
  test`. A suite `include`s the `src/*.cyr` files it needs directly. The four
  `osc_*` modules are the one exception: they share `tests/oscillator.tcyr`.
- `src/main.cyr` — the smoke entry, **not** where library code goes. It includes
  `dist/naad.cyr` (plus `lib/hisab.cyr` and `lib/goonj.cyr`) and runs a tiny
  cross-layer check, proving the bundle compiles and links the same way a
  consumer would use it.
- `dist/naad.cyr` + `dist/naad.deps` — the distlib bundle and its stdlib sidecar.
  Both are **tracked artifacts**, generated by `cyrius distlib` from the
  `[lib].modules` list in `cyrius.cyml`. Never hand-edit them.
- `lib/` — vendored stdlib (from the toolchain pin) and resolved deps, written by
  `cyrius deps`. Never hand-edit.
- `rust-old/` — original Rust source preserved for parity checks. Do not modify;
  it's the reference oracle, never a build target.

## Adding a feature

1. Edit the owning `src/<module>.cyr` (or add a new module and list it in
   `[lib].modules` in `cyrius.cyml`, in dependency order).
2. Cross-check parity against the corresponding file in `rust-old/src/`.
3. Add assertions to `tests/<module>.tcyr` — a new module needs a new suite;
   `cyrius test` picks it up with no registration step.
4. `cyrius test tests/<module>.tcyr` while iterating, then bare `cyrius test`.
5. `cyrius distlib` to regenerate `dist/naad.cyr` and `dist/naad.deps`, then
   rebuild `src/main.cyr` — the smoke binary compiles the *bundle*, so it will
   not see your change until the bundle is regenerated. `cyrius distlib --check`
   verifies the tracked bundle is current without writing.
6. `cyrius audit` before proposing the change — it sweeps fmt, lint, docs, tests
   and bench in one pass, and is the gate the change has to clear anyway.
7. Bump `VERSION` and add a CHANGELOG entry before tagging.

## Quality commands

| Command | What it does |
| --- | --- |
| `cyrius audit` | full sweep: fmt / lint / docs / tests / bench |
| `cyrius fmt <file>.cyr --check` | reports whether the file is canonically formatted |
| `cyrius lint <file>.cyr` | static analysis |
| `cyrius doc --check <file>.cyr` | documented / undocumented public fn counts |
| `cyrius vet src/main.cyr` | audit the include dependency graph |
| `cyrius deny src/main.cyr` | enforce project dependency policy |
| `cyrius coverage` | reference coverage over `src/` |
| `cyrius bench tests/<f>.bcyr` | run a benchmark harness |

**`cyrius fmt <file>.cyr` rewrites that file in place and prints nothing.** It is
not a way to preview canonical output — use `--check` for the non-destructive
form. (There is no `-w` flag; any doc or hint text suggesting one is wrong.)

## After a toolchain or dependency bump

A green suite is not evidence the bump was inert. Re-run `cyrius deps` to
re-vendor `lib/`, then verify it file-by-file against the *pin's own* snapshot at
`~/.cyrius/versions/<pin>/lib` — diffing the old pin against the new one can look
tidy and still hide a half-synced tree. Behavior inherited from a dependency
(new guards, new failure returns where a call previously always succeeded)
shows up as a segfault or silent divergence, not as a red test, so read the
dependency's changelog and pin the new contract with assertions.

See [`../adr/template.md`](../adr/template.md) when a non-trivial design choice
deserves an ADR.
